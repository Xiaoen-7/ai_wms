开跑前 3 分钟：npm run dev → http://localhost:5173 ｜ 纯前端 Mock，刷新=库存/单据复位 ｜ 「我的→重置演示数据」一键全清 ｜ 所有"扫码"都是点按钮——点一下 = 扫码枪过一件货；盘点页另有连扫模式（逐件自动累加，货架上有几件就扫得出几件）。演示条码是确定性轮换。

产品一句话：给服装连锁门店用的库存手机工作台——进货、盘点、调拨、退货四个动作全部"扫码即记账"，账本每次变动都有单据可追溯。

一、角色与一天的时序

09:30 快递到店 → 剧本A 进货入库（店员）　 账本：可售 ↑
11:00 总部调拨到 → 剧本C 调拨收货（店员）　账本：在途 → 可售
14:00 顾客来退货 → 剧本D 退换货（店员/店长）账本：可售 ↑ 或 次品 ↑
21:30 打烊 ────→ 剧本B 盘点（店长）　　　 账本：账实校准
核心心智模型：库存账四个口袋——可售 / 在途 / 次品 / 待清理挂账。所有操作只是把件数在口袋间搬动或进出，每次搬动留一张单据（守恒）。

二、剧本 A：进货入库（店员，最高频）

场景：供应商货车到店。整箱多 SKU 走收货单核点；零散几件走快捷扫码。两条链路的差异口径完全一致。

跟着跑 A-1（含差异挂账）：功能页 → 收货单 → 点开 ASN20261019001 → 点箱码标签扫 1003 → 试「扫一条错误箱码（演示）」→ 把第三箱实点从 6 改成 5（行内变红「数量不符」）→ 确认入库 → 按实点入 5 件，差额 1 件生成 CY 差异单挂账。

跟着跑 A-2（快捷扫码）：功能页大按钮 → 扫码出商品卡 → 把实收改成 ≠ 应收 → 确认入库 → 差额同样生成 CY 差异单（toast 带单号，首页 +1）。

这条链在保护什么：按实点入库（送10实点8 → 入8挂2，账上不出现纸面货——面试词：账实分离，差异挂账）；未登记条码三原则——不静默丢弃、同码去重累加、不自动追认入账。

三、剧本 P：未匹配条码分件处置（店长，v0.4.8）

场景：同一条码扫了 2 次（×2 累加），但店长核实后只有 1 件是真异常——逐条留痕，件数不丢失（PRD 3.7）。

在保护什么：不自动追认入账——每一条异常都必须经店长人工处置；×N 打包处置会丢件数，所以按件拆分留痕；48h 未核实自动升级提醒总部。

四、剧本 B：盘点（店长，唯一的账实校准器）

场景：月末全店大盘（3 小时→10 分钟）；或怀疑某几个款有差异想复核。账本平时靠事件记账，盘点是唯一的"校准器"——它不听账本说什么，而是重新数一遍货架。

跟着跑 B-1（全店盘 + 对账 + 盘平）：扫码盘点 → 连扫补完剩余 5 款 → 结束盘点 → 覆盖率 100%、盘亏 2 / 盘盈 1（预埋真实货差剧情，每条附人话归因）→ 确认差异落账（生成 TZ 调整单）→ 回盘点页「重新开单」→ 再连扫一轮 → 盘平 0/0——账实校准后差异源消失，不该每轮都亏同一件。

跟着跑 B-2（故意触发护栏 + 驳回）：重新开单 → 连点 3 次「扫码盘点」（可能都落在同一款）→ 结束盘点 → 覆盖率仅 8%（1/12）、-2 盘亏，黄条提示"未盘的不会被修改" → 确认差异 → 强制弹窗〔驳回重盘〕〔我知悉，仍要确认〕→ 点驳回：结果作废、库存不动、已盘记录保留，状态自动回「盘点中」，回去直接继续扫（v0.4.6）。

这条链在保护什么：三层模型（账本 ≠ 货架实况 ≠ 扫码计数——系统绝不按账本"补齐"实盘，那是抄答案）｜冻结快照（对账只跟开单那刻的照片比）｜盲盘（防照本凑数）｜未盘 ≠ 盘亏｜落账护栏（防"半轮盘点一键砍账"）｜重新开单 = 新一轮（面试金句：照片是给账本此刻的样子留证）｜连扫 = 扫码枪连发的替身（真实门店靠扫码枪每秒 3~5 次连发或 RFID，快但不作弊）。
每日结业小盘 = PRD 5.2.3 快速盘点（范围选择，覆盖率分母=范围内 SKU），尚未实现——面试可主动讲规划。

五、剧本 C：调拨收货（店员，门店间移货）

这条链在保护什么：签收即入库（单据状态与记账解耦，差异不阻塞入库——v2.2 重画状态机的根因）；守恒——有差时 可售+实到、在途-应到、挂账+差额，合计仍不变。

六、剧本 D：顾客退货 + 次品处理（店员/店长）

场景：连衣裙吊牌完好 → 入回可售；衬衫包装破损 → 归次品；小票丢了 → 人工录入待复核。演示扫码按固定顺序轮换：①连衣裙有原单 ②衬衫有原单 ③大衣查无原单 ④开衫有原单。

次品处理（店长）：次品登记 → 浮动＋登记（原因必填；口径 = 可售划入次品，守恒内部转移）→ 待处理条目点「促销处理」→ 已促销处理留痕、次品账扣减。

这条链在保护什么：验退反查杜绝入错款｜吊牌破损强制进次品不能回流可售｜无原单不拦账但强制留复核痕迹（24h 补原单解除）｜次品账独立可对接总部促销。

七、剧本 E：数据查看（店长每天打开第一眼）

首页 6 格待办点击直达（任何数据 ≤2 次点击）；差异单 → 首页「待确认差异」直达；未匹配条码 → 各页共用的待处理清单入口。

八、面试串联（30 秒）

"这是一家服装连锁门店的库存工作台。进货扫码按实点入库，差异挂账不拦账；调拨签收即入库，差额进挂账科目；退货扫码反查原销售单，吊牌完好回可售、破损归次品、无原单先入账再待复核；盘点是唯一校准器——开单冻结快照、盲盘计数、自动对账归因、店长确认才落账，没盘完有护栏拦着。库存四科目守恒，每次变动有单据号可追溯。"

已知缺口（主动说，比被问出来强）：① 快速盘点（5.2.3 每日小盘）未实现 ② 数据为 Mock 内存态，刷新复位（持久化的只有条码待处理清单与退货待复核清单）③ 对账页店员引导未上页面。配套：简岸门店WMS-demo面试问答卡.md（6 问）。
