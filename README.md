# 简岸门店 WMS —— 服装连锁门店库存工作台

> 一个"扫码即记账"的门店库存管理系统：进货、盘点、调拨、退货四个动作全部扫码完成，账本每次变动都有单据可追溯。
> 本项目为 AI 辅助开发的作品集项目（产品经理视角：PRD → 开发 → 验收 → 迭代全流程），纯前端 Mock 实现。

**在线演示**：https://jianan-wms-demo.app.workbuddy.host/

---

## 这个系统解决什么问题

服装门店的库存账经常"对不上"：货到了没空录、卖漏了没人记、盘点靠 Excel 手工对。本产品把库存账拆成**四个科目**（可售 / 在途 / 次品 / 待清理挂账），所有操作只是把件数在科目间搬动，**每次搬动都留一张单据**——账实永远守恒，每一笔都能追溯。

## 核心业务剧本（对应实操指南）

| 剧本 | 角色 | 链路 | 关键机制 |
|------|------|------|----------|
| A 进货入库 | 店员 | 收货单核点 / 快捷扫码 | 按实点入账，差额生成 CY 差异单挂账，不拦账 |
| B 盘点 | 店长 | 冻结快照 → 盲盘连扫 → 自动对账 → 落账 | 未盘≠盘亏、半盘护栏强制弹窗、驳回=同轮补扫、落账后盘平 0/0 |
| C 调拨收货 | 店员 | 签收即入库 | 实到几件入几件，差额进挂账科目，合计守恒 |
| D 退换货 | 店员/店长 | 扫码反查原销售单 → 吊牌分流 | 破损强制归次品；查无原单自动识别商品+强制待复核 |
| P 条码处置 | 店长 | 未匹配条码四选一人工处置 | 不静默丢弃、同码累加、分件处置逐条留痕 |

## 几个值得看的设计决策

- **盘点三层模型**：账本（记录）≠ 货架实况（物理世界）≠ 扫码计数。扫码扫的是货架，系统绝不按账本"补齐"实盘——那是抄答案，错上加错
- **冻结快照**：盘点对账只跟"开单那一刻的账本照片"比，盘点期间的出入库不污染差异
- **半盘护栏**：没盘完的结果没有资格被静默确认——防"半轮盘点一键砍账"
- **条码即商品**：查无原单的人工录入，商品由条码自动识别填入（改选需二次确认），从根上消灭"选错商品"
- **差异两链路同口径**：收货单核点与快捷扫码的差额都走同一张差异单体系，口径不分裂

## 技术栈与结构

```
Vue 3 + Vite + Vant 4（移动端 H5）＋ 纯前端 Mock 数据层（内存态，刷新复位）
```

```
demo-code/jianan-wms-mobile/   源码
  ├── src/mock/wms.js          核心数据层（~1400 行：四科目账本/状态机/差异单/盘点快照）
  ├── src/views/               页面（首页/收货/盘点/调拨/退货/次品/库存）
  ├── smoke-full.mjs           全链路 E2E：34 项断言，交付门槛=全绿
  └── capture-guide.mjs        图解指南截图工具链（干净版+标注版双份输出）
docs/wms/                      产品文档（见下）
archive/旧版文档/              PRD 历史版本留痕
```

## 快速开始

```bash
cd demo-code/jianan-wms-mobile
npm install
npm run dev        # http://localhost:5173
node smoke-full.mjs  # 全链路 E2E（需先启动 dev server）
```
