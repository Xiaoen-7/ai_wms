# 简岸门店 WMS · 实操指南

> 版本 v1.2（对应 Demo v0.4.7，2026-10-26）  
> 架构：**用户路径**（按业务事件组织剧本），不是功能分类——你跑的不是"功能清单"，是店员/店长的真实一天。  
> 每个剧本五段：**场景**（什么时候发生）→ **跟着跑**（步骤+你会看到什么）→ **这条链在保护什么**（面试点）→ **数据去哪查**。

## 〇、开跑前 3 分钟：机制说明

| 事项   | 说明                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 启动   | `npm run dev` → <http://localhost:5173>                                                                                                 |
| 数据机制 | 纯前端 Mock，**刷新页面 = 库存/单据复位**；未匹配条码清单、待复核清单持久化（localStorage），点「我的 → 重置演示数据」一键全清                                                           |
| 扫码模拟 | 所有"扫码"都是**点按钮**——点一下 = 扫码枪过一件货；盘点页另有**连扫模式**（模拟扫码枪连发，逐件自动累加）。货架上有几件就扫得出几件，扫满再扫会提示"已扫不出更多"。演示条码是**确定性轮换**的（不是随机），指南里的"第 1 扫/第 2 扫"就是这个顺序 |
| 面试兜底 | 数据存哪？→ 真实方案接后端数据库，demo 用 Mock 隔离了数据层，架构分层不变                                                                                             |

**产品一句话**：给服装连锁门店用的库存手机工作台——进货、盘点、调拨、退货四个动作全部"扫码即记账"，账本每次变动都有单据可追溯。

## 一、角色与一天的时序（先建立全局感）

```
09:30  快递到店 ──→ 剧本A 进货入库（店员）      账本：可售 ↑
11:00  总部调拨到 ─→ 剧本C 调拨收货（店员）      账本：在途 → 可售
14:00  顾客来退货 ─→ 剧本D 退换货（店员/店长）   账本：可售 ↑ 或 次品 ↑
21:30  打烊 ──────→ 剧本B 盘点（店长）          账本：账实校准
任何时候 ─────→ 剧本E 查数据（首页/库存）        账本：只读
```

**核心心智模型**：库存账有四个口袋——**可售 / 在途 / 次品 / 待清理挂账**。所有操作都只是把件数在口袋间搬动或进出，每一次搬动都留一张单据。这个"守恒"思想是整个产品的灵魂（面试高频）。

## 二、剧本 A：进货入库（店员，最高频）

**场景**：供应商货车到店，随箱附送货单。货可能是整箱多 SKU（走收货单流程），也可能是零散几件（走快捷扫码）。

### 跟着跑 A-1：收货单核点入库（含差异挂账）

| 步 | 操作                                | 你会看到                                                                   |
| - | --------------------------------- | ---------------------------------------------------------------------- |
| 1 | 功能页 → **收货单**                     | 2 张待收货单（ASN20261019001 / 20261020002），显示应收件数与箱数                        |
| 2 | 点开第一张                             | 箱码列表 BOX-AW-1001~1003，已扫箱打勾                                            |
| 3 | 逐个点箱子"扫码"（演示按钮）                   | 箱子变已扫，行内显示 SKU 与应收数                                                    |
| 4 | 点 **「扫一条错误箱码（演示）」**               | 弹"未匹配商品主数据"→ 挂入待处理清单（**不静默丢弃**）                                        |
| 5 | 把第三箱**实点从 6 改成 5** → 点 **「确认入库」** | 行内出现红色"数量不符"→ 按实点入库 5 件，**差额 1 件生成 CY 差异单挂账**                          |
| 6 | 首页点 **「待确认差异」**（变红 1）直达差异页        | CY 单列表：供应商/来源/差异行（送货单 6 · 实点 5，-1 件）；点 **「确认差异」** → 已确认留痕（与供应商核实后挂账追偿） |

### 跟着跑 A-2：快捷扫码入库（单件直入）

| 步 | 操作                           | 你会看到                                                        |
| - | ---------------------------- | ----------------------------------------------------------- |
| 1 | 功能页 → 扫码入库大按钮（/receipt-scan） | 扫出商品卡 + 送货单应收数                                              |
| 2 | 点 **「扫一条未登记条码（演示）」**         | 同样挂待处理清单（与收货单页**共享同一份**）                                    |
| 3 | 把实收改成 ≠ 应收 → 确认入库            | 按实收入库；**差额同样生成 CY 差异单**（toast 带单号，首页待确认差异 +1）——两条入库链路差异口径一致 |

### 差异从哪看（两链路同口径）

首页「待确认差异」→ **收货差异页**：所有 CY 单（收货单核点 / 快捷扫码两种来源）集中展示，实点入库、差额挂账追偿，店长核实后点确认留痕。

### 这条链在保护什么

- **按实点入库**：送 10 实点 8，入 8 挂 2——账上不出现"纸面货"（面试词：账实分离，差异挂账）
- **未登记条码三原则**：不静默丢弃、同码去重累加、不自动追认入账（店长四选一人工处置，48h 未处理升级总部）

### 数据去哪查

首页「待收货」待办 → 收货单列表；**差异单 → 首页「待确认差异」直达收货差异页**；未匹配条码 → 「我的」附近各页共用的待处理清单入口。

## 三、剧本 B：盘点（店长，账实校准器）

**场景**：月末全店大盘（3 小时→10 分钟）；或怀疑某几个款有差异想复核。**账本平时靠事件记账，盘点是唯一的"校准器"**——它不听账本说什么，而是重新数一遍货架。

### 跟着跑 B-1：全店盘点 + 对账

| 步 | 操作                                        | 你会看到                                                                                                                        |
| - | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1 | 功能页 → **扫码盘点**                            | 任务卡：PD 单号、进度 7/12（预置了部分已盘）；**此时没有「重新开单」按钮——它只在上轮盘点完成后才出现**                                                                  |
| 2 | 点 **「连扫模式（模拟扫码枪连发）」**                     | 自动逐件补扫剩下 5 个 SKU（每件约 0.6 秒），清单数字实时跳动——就像扫码枪沿货架连发；扫完自动停，提示"本轮连扫 N 件，货架已全部扫完"（12/12）。不想连扫也可手动点 **「扫码盘点」** 大按钮：每点一次 = 扫过货架上的一件 |
| 3 | 顺手点一次 **「扫一条未登记条码」**                      | 挂入共享待处理清单（跨页共享同一份）                                                                                                          |
| 4 | 货架扫完 → 结束盘点                               | 进入**盘点对账**页：顶部覆盖率 100%、差异 SKU 3、**盘亏 2 / 盘盈 1**                                                                             |
| 5 | 看差异明细                                     | 大衣黑S 账面 6→实盘 5（-1）、衬衫米白M 9→10（+1）、开衫浅灰S -1——这是 demo 预埋的**真实货差剧情**（昨售漏记 / 到货漏登 / 样衣借出），每条附一句人话归因；灰色"归因依据"默认折叠（店长追查用）         |
| 6 | 点 **「确认差异」**                              | 直接落账（覆盖率 100% 无弹窗）：生成 TZ 调整单，账面向实盘对齐                                                                                        |
| 7 | 回盘点页 → **现在才有「重新开单」** → 点它 → 再连扫一轮 → 结束盘点 | **盘平 0/0，无差异**——账实校准后差异源消失，不该每轮都亏同一件（想再看差异剧情：我的 → 重置演示数据）                                                                   |

> **为什么不再是巨亏**：扫码扫的是**货架**，不是账本——货架上有几件就扫得出几件（扫满再扫会提示"已扫不出更多"）。跑完全盘，暴露的就是真实的账实小差异，而不是"每款只记 1 件"式的假巨亏。



> **落账之后差异去哪了**（v0.4.5）：点「确认差异」落账 = 账实校准，这几个款的差异源随之消失——再开新一轮全盘会得到"盘平，无差异"（这是对的：账已经对齐了，不该每轮都亏同一件）。想再看差异剧情：**「我的 → 重置演示数据」**&#x4E00;键回到初始剧本。连扫过程中"已盘 SKU"数字不动是正常的——连扫扫的是**件**、进度按**款**计数，一款十几件时数字都加在同款上。

### 跟着跑 B-2：故意触发护栏（理解 v0.4.1）

| 步 | 操作                                 | 你会看到                                                                          |
| - | ---------------------------------- | ----------------------------------------------------------------------------- |
| 1 | 重新开单 → 点 **「扫码盘点」3 次**（只扫几件，可能都落在同款）→ 结束盘点 | 对账页覆盖率远低于 100%（实测 8%，1/12），黄条提示"只盘了 1/12 个 SKU，未盘的不会被修改"                           |
| 2 | 点 **「确认差异」**                       | **强制弹窗**："本轮只盘了 X/12…未盘不会被修改…已盘差异合计…〔驳回重盘〕〔我知悉，仍要确认〕"                         |
| 3 | 点 **〔驳回重盘〕**                       | 结果作废、库存不动、回盘点页——账本毫发无损；**已盘记录保留，回去直接继续扫**（v0.4.6：驳回 = 同一轮补扫，状态自动回「盘点中」，按钮不再灰） |

### 这条链在保护什么

- **三层模型**：账本（记录）≠ 货架实况（物理世界）≠ 扫码计数（店员扫出来的）——扫码扫的是货架，差异 = 货架 vs 账本，系统绝不按账本"补齐"实盘（那是抄答案，错上加错）
- **冻结快照**：对账只跟"开单那一刻的账本照片"比，盘点期间的出入库不污染差异（顺序无关）
- **盲盘**：扫码时不给账面数，防照本凑数；多扫少扫静默，对账统一揭晓
- **未盘 ≠ 盘亏**：只对已盘 SKU 出差异（v0.3.1 修复过"未盘按 0 算出 -22 假亏"的缺陷）
- **落账护栏**（v0.4.1）：没盘完的结果没有资格被静默确认——这是防止"半轮盘点一键砍账"
- **重新开单 = 新一轮**：旧照片作废，因为上一轮落账已改变账本（面试金句：照片是给账本此刻的样子留证）
- **连扫 = 扫码枪连发的替身**（v0.4.4）：真实门店一次扫几百上千件，靠的是扫码枪每秒 3~5 次连发（或 RFID 批量读取），不是点按钮——demo 的连扫模式模拟的就是这个物理动作，快但不作弊

### 说明

每日结业小盘（只盘部分款）对应 PRD 5.2.3 快速盘点，**尚未实现**——当前护栏按全店口径算覆盖率，这是已知缺口。面试可以讲："我知道每日小盘场景，规划是范围选择 + 覆盖率分母按范围算，和护栏天然兼容。"

## 四、剧本 C：调拨收货（店员，门店间移货）

**场景**：旗舰店的货调给万象城店（调出方只管发货），银泰店调给我 5 件（我是调入方，要开箱点货）。

### 跟着跑

| 步 | 操作                                     | 你会看到                                              |
| - | -------------------------------------- | ------------------------------------------------- |
| 1 | 底部 Tab → **调拨**                        | 3 张单：我发出的（在途/已入库）、我接收的（已签收）                       |
| 2 | 点开 **DB20261017002**（银泰→我，已签收）         | 明细 2 个 SKU 共 5 件，提示"演示可点下方条码模拟逐件扫描"               |
| 3 | 连点演示条码 **5 次**（扫满 5 件）                 | 每点 1 次记 1 件；少扫几件也可以（差异演示）                         |
| 4 | 点 **「确认收货并入库」**（扫不满时按钮叫"确认收货（差额挂账入库）"） | 单据 → 已入库；实到几件入几件可售；应到减在途池；**差额进"待清理挂账量"科目**并生成差异单 |

### 这条链在保护什么

- **签收即入库**：单据状态与记账解耦——有差异照样先入库，差额走差异单，货不游离在账外（v2.2 重画状态机的根因）
- **守恒**：一致时 可售+N/在途-N 合计不变；有差时 可售+实到、在途-应到、挂账+差额，合计仍不变

### 数据去哪查

调拨列表筛选状态；库存页筛「在途」「挂账」科目看余量。

## 五、剧本 D：顾客退货 + 次品处理（店员/店长）

**场景**：顾客拿一件连衣裙来退（吊牌完好）→ 入回可售；另一件衬衫包装破了 → 归次品；还有一位小票丢了 → 人工录入待复核。**扫码验退的演示条码按固定顺序轮换 4 种场景**：①连衣裙有原单 ②衬衫有原单 ③大衣查无原单 ④开衫有原单。

### 跟着跑 D-1：扫码验退（连点 4 次体验全场景）

| 步 | 操作                              | 你会看到                                     |
| - | ------------------------------- | ---------------------------------------- |
| 1 | 功能页 → **退换货** → **扫码验退**，第 1 扫  | **原销售单信息卡**：原单号/商品/批次/购买时间（这就是"反查"）      |
| 2 | 选"吊牌完好"，可选开"换货"挑新 SKU           | 换货 = 一退一进两笔事件（原 SKU 入回 + 新 SKU 可售扣减）     |
| 3 | 点 **「入回原库存」**                   | 生成 TH 退货单，事件回执展示；库存页该 SKU 可售 +1          |
| 4 | 第 2 扫 → 选"破损或已拆封" → 点 **「归次品」** | 次品账 +1，**自动生成一条次品登记**（CP 单，待处理）          |
| 5 | 第 3 扫 = **大衣查无原单** → 人工录入表单     | **退货商品已按条码自动识别填入**（条码即商品，改选需二次确认）；先试**不勾"标记待复核"直接提交** → 被拦截（数据层强校验）；勾上才能提交 |
| 6 | 第 4 扫正常验退                       | 完整走一遍                                    |

### 跟着跑 D-2：待复核闭环

| 步 | 操作                        | 你会看到                  |
| - | ------------------------- | --------------------- |
| 1 | 退换货主页 → **待复核清单**         | 刚才人工录入那条，状态待复核        |
| 2 | 点 **「补录原单，解除标记」** → 输入原单号 | 状态 → 已复核，留痕"已补原单 XS…" |

### 跟着跑 D-3：次品登记与促销（店长）

| 步 | 操作                       | 你会看到                                                                 |
| - | ------------------------ | -------------------------------------------------------------------- |
| 1 | 功能页 → **次品登记**           | 汇总头（待处理/已促销件数）+ 列表 + 每条的**处理留痕**                                     |
| 2 | 点浮动 **＋** 登记：先留空原因提交     | **被拦："次品原因必填"**；填原因后成功                                               |
| 3 | 注意口径                     | 手工登记 = **可售划入次品**（守恒内部转移，合计不变）；退货归次品 = 外部流入（次品 +N，合计 +N）——两种来源科目方向不同 |
| 4 | 点某条 **「促销处理（总部季度低价清货）」** | 状态 → 已促销处理 + 留痕，次品账同步扣减                                              |

### 这条链在保护什么

- **验退反查**：退货必须挂到原销售单，杜绝"随便入回哪个款"（入库 SKU ≠ 原单 SKU 会进 R2 对账规则）
- **条码即商品**（v0.4.9）：查无原单时退货商品由条码自动识别填入，店员不存在"选错"的机会；确需改选要二次确认，且 24h 补录原单环节会对账暴露
- **吊牌分流**：破损货强制进次品，**不能混进可售**再卖给下一位顾客
- **无原单不拦账但要留痕**：先入账（顾客体验）+ 强制待复核（风险可控），24h 补原单解除
- **次品账独立**：次品有自己的人口普查，对接总部季度促销，处理全程留痕

### 数据去哪查

首页「退货待复核 / 次品待处理 / 今日退货」三个数字直达；次品全貌 → 次品登记页。

## 七、全局闭环（面试串联版，30 秒）

> "这是一家服装连锁门店的库存工作台。**进货**扫码按实点入库，差异挂账不拦账；**调拨**签收即入库，差额进挂账科目；**退货**扫码反查原销售单，吊牌完好回可售、破损归次品、无原单先入账再待复核；**盘点**是唯一校准器——开单冻结快照、盲盘计数、自动对账归因、店长确认才落账，没盘完有护栏拦着。库存账四个科目（可售/在途/次品/挂账）守恒，每次变动都有单据号可追溯。首页聚合待办与今日动态，任何数据两步可达。"
