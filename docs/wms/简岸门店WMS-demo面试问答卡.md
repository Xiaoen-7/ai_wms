# 简岸门店 WMS demo · 面试问答卡

> 版本：v1.0（2026-10-22，对应 demo v0.3.1）
> 用法：面试前直接背。每题先给一句话答案，再给展开版。

---

## Q1. 为什么是网页（H5）而不是 App？

**一句话**：MVP 思维——先用 H5 快速验证业务方案，验证通过再评估要不要上原生壳。

**展开**：这个 demo 的核心要验证的是业务流程（扫码收货、盲盘、差异归因、落账闭环），不是性能极限。H5 开发快、免安装、店员扫个码就能用，适合快速试错。UI 组件选型时按原生交互规范挑了 Vant 4（动作面板、扫码页、下拉刷新都贴合手机习惯），保证体验不掉队。如果后续验证通过、需要调用摄像头深度 API 或离线能力，再套混合壳或转原生，方案平滑升级。

## Q2. 讲讲扫码盘点的用户故事和业务流程

**用户故事**：作为一名店长，我希望用手机逐件扫码代替手工抄单，系统自动计数、自动比对账面并归因差异，这样盘点从 2 小时缩短到 10 分钟，且每个差异都有证据链可查。

**五步流程（每步都有设计理由）**：

| 步骤 | 做什么 | 设计理由 |
|---|---|---|
| ① 开单 | 给当前账本"拍照"锁定基准 | 防止盘点期间的出入库污染对账 |
| ② 逐件扫码 | 盲盘，不显示账面数 | 防止店员照着账本凑数 |
| ③ 陌生码挂起 | 扫到不认识的箱码先进待处理区 | 件数不丢，48h 未处理自动升级 |
| ④ 结束对账 | 实扫数 − 照片 = 差异，自动归因 R1/R2 | 差异有归因、有证据，不是一笔糊涂账 |
| ⑤ 店长处置 | 认可 → 确认落账；不认可 → 驳回重盘 | 差异必须经人确认才动账本 |

## Q3. 重新开单后已盘清单清空、12 件 SKU 要重扫，为什么？

**一句话**：重新开单不是"重置"，是"开启新一轮"——上一轮落账后账本已经变了，旧照片过期了，必须重拍重扫。

**展开（连衣裙时间线）**：
1. 上午 10:00 开单，照片 A = 连衣裙 8 件。
2. Round 1 实盘扫到 7 件 → 盘亏 1。
3. 店长确认落账 → **账本被修正成 7**。从此照片 A（8）就是过期基准。
4. 晚上 21:00 新订单到货入库 2 件 → 账本变成 9。
5. 重新开单 → 拍照片 B = 9（此刻账本的最新快照）。
6. 第二轮实盘扫到 9 件：跟照片 A 比 = +1 假盘盈（货没错，照片过期）；跟照片 B 比 = 0，账实相符。

**面试金句**：照片不是"拍给盘点用的"，是"给账本此刻的样子留证"。账本每落一次账、每进一次货，旧照片就失效一次——重新开单的本质是给变过的账本重新留证。状态机上"已完成"是终态，保证每份对账结果对应唯一一张快照，可追溯、不会被拿旧结果凑账。

**延伸**：只想盘一部分的场景 = PRD 5.2.3 快速盘点（按范围局部盘），同一状态机直接支持，属后续规划。

## Q4. 盲盘扫多了怎么不提示？店员不慌吗？

**一句话**：这是故意的。盲盘只负责"忠实计数"，揭晓答案留给对账页，一次性统一归因。

**展开**：如果扫的过程中就提示"多了 1 件"，店员会停下手里动作去查账、甚至偷偷删数凑平，盲盘就废了。所以扫码阶段只做静默计数（连扫错都允许挂起），盘盈盘亏统一在对账时揭晓，并给出归因和证据链。这样数据是干净的，差异解释权在对账页。

## Q5. 只盘了一部分 SKU，没盘的为什么不算盘亏？

**一句话**：没扫 ≠ 没有。差异只对"已盘 SKU"计算，未盘的单独报数，不进盘亏。

**展开**：v0.3.0 曾把未盘 SKU 按实盘 0 处理，算出 -25 件的离谱盘亏——这是把"没数"当成了"数出 0"。修正后：差异明细只包含已扫 SKU；未盘 SKU 数量在概览单独提示（"本轮未盘 N 个 SKU"），提示店长要么补盘、要么明确接受局部盘。边界感：系统不替人做"货丢了"的判断。

## Q6. 差异确认后，怎么保证真的动了账本？

**一句话**：确认落账生成一张 TZ 调整单，逐 SKU 把账面向实盘对齐，账实校准事件随差异量变化，可追溯。

**展开**：v0.3.0 曾有"确认后 toast 说已更新、库存实际没动"的假落账。v0.3.1 修正：确认 → 生成调整单（如 TZ202610220001）→ 逐 SKU 修 sellable → 返回"调整单号 + 本次落账 SKU 数"，toast 明示。驳回则不落账、单据回到重盘。核心原则：**差异必须经"确认"这个人类动作才能改账本，且每次改账留单据号可追溯**。
